# ESS 배터리 Cycle Life 예측

## 프로젝트 개요

배터리의 초기 100사이클 측정값으로 셀의 전체 Cycle Life를 예측하고, 다른 실험 배치에서 예측 성능이 유지되는지 평가했습니다. 분석 결과를 바탕으로 어떤 초기 신호가 수명과 관련되는지 살펴보고, 셀 점검 및 교체 계획에 활용할 때의 가능성과 한계를 정리합니다.

| 항목 | 내용 |
| --- | --- |
| 데이터 | MIT–Stanford Battery Dataset의 지정된 3개 batch |
| 입력 | 초기 사이클의 방전 용량, ΔQ, 내부저항, 온도, 충전 신호 및 충전 정책 |
| 예측 대상 | 데이터에 기록된 `cycle_life` (사이클 수) |
| 문제 유형 | 회귀 |
| 학습 데이터 | Batch 1 — 2017-05-12 |
| 최종 평가 데이터 | Batch 2 — 2018-02-20 |
| 추가 평가 데이터 | Batch 3 — 2018-04-12 |

선택 모델은 초기 6개 피처를 사용한 Random Forest입니다. Batch 2 MAPE는 33.11%, Batch 3 추가 평가 MAPE는 14.10%였습니다. Batch 2에 짧은 수명 셀이 집중되어 있어, 이 모델은 짧은 수명 구간에서 수명을 실제보다 길게 예측하는 경향을 보였습니다.

## 데이터 구성 및 전처리

| Batch | 파일 | 셀 수 | `cycle_life` 라벨 보유 |
| --- | --- | ---: | ---: |
| 1 | `2017-05-12_batchdata_updated_struct_errorcorrect.mat` | 46 | 46 |
| 2 | `2018-02-20_batchdata_updated_struct_errorcorrect.mat` | 47 | 39 |
| 3 | `2018-04-12_batchdata_updated_struct_errorcorrect.mat` | 46 | 44 |
| 합계 |  | 139 | 129 |

분석에서는 셀당 한 행을 만들고, `cycle_life`가 결측인 10개 셀도 통합 데이터와 EDA에 보존했습니다. 지도학습과 성능 계산에서만 타깃 결측 행을 제외했습니다. 원본 MAT 파일은 대용량이므로 저장소에 포함하지 않습니다. [Kaggle 데이터셋](https://www.kaggle.com/datasets/itshpark/data-driven-prediction-of-battery-cycle)에서 내려받아 `data/`에 놓으세요. 다운로드 파일명과 매핑은 [data/README.md](data/README.md)를 참고하세요.

## 데이터 분석 결과와 시사점

129개 라벨 셀의 Cycle Life 평균은 약 834사이클, 중앙값은 828사이클이며 범위는 392–1,935사이클입니다. 단수명(<500) 셀은 28개(21.71%), 중간 수명(500–1,000) 셀은 65개(50.39%), 장수명(>1,000) 셀은 36개(27.91%)였습니다. 이 분포는 batch별로 크게 달랐습니다.

| Batch | 라벨 셀 | 평균 Cycle Life | 중앙값 | 범위 | 단수명(<500) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 46 | 844.7 | 858.5 | 534–1,227 | 0 |
| 2 | 39 | 565.7 | 472.0 | 392–1,186 | 28 |
| 3 | 44 | 1,059.7 | 1,005.5 | 541–1,935 | 0 |

Batch 2 테스트 셀 중 71.8%가 500사이클 미만인 반면, Batch 1 학습 셀에는 그 구간의 사례가 없습니다. 따라서 Batch 2 성능 저하는 단순히 평균 오차가 커진 현상을 넘어, 학습 중 관찰하지 못한 수명 구간을 예측해야 하는 분포 이동 문제와 연결됩니다. Batch 3는 Batch 2와 반대로 수명이 긴 셀이 많은 편입니다.

### 방전 용량 열화와 Knee

대부분의 셀에서 방전 용량 `QD`는 사이클이 증가하면서 감소했습니다. 전체 열화 곡선에서 추정한 Knee의 그룹별 중앙값은 단수명 약 348사이클, 중간 수명 632사이클, 장수명 884사이클이었습니다. 후기 QD 감소 속도의 중앙값은 단수명 그룹 2.045 mAh/cycle, 장수명 그룹 0.582 mAh/cycle로 나타났습니다. 이는 짧은 수명 셀에서 급격한 용량 저하가 더 일찍 나타나는 경향과 일치합니다.

Knee와 후기 열화 속도는 셀의 전체 수명에서 계산한 사후 분석값입니다. 조기 예측 모델에 사용하면 미래 정보를 미리 사용하는 누수가 생기므로 입력 피처에서는 제외하고, 열화 특성을 설명하는 EDA 결과로만 사용했습니다.

### 초기 ΔQ 신호

초기 100사이클의 `ΔQ(V) = QD_cycle100(V) − QD_cycle10(V)` 로그 분산은 Cycle Life와 Pearson 상관계수 -0.851을 보였습니다. 초기 전압별 방전 용량 변화가 수명과 강한 연관성을 가질 수 있다는 뜻으로, ΔQ 로그 분산을 단일 피처 모델과 기본 다중 피처 모델에 포함했습니다. 상관관계는 인과관계를 의미하지 않으며, 단일 피처 모델의 배치 간 성능도 별도로 확인했습니다.

### 충전 정책과 온도·저항 신호

충전 정책의 C1, C2, 전환 SOC를 추가한 Elastic Net을 기본 피처 모델과 비교했습니다. Batch 1 hold-out MAPE는 기본 Elastic Net과 동일하게 10.77%였고, Batch 2 MAPE는 정책 피처 모델이 74.63%로 기본 Elastic Net의 67.77%보다 높았습니다. 이번 데이터와 분할에서는 정책 변수 추가가 배치 간 일반화를 개선하지 못했습니다. 이를 충전 속도가 수명에 영향을 주지 않는다는 결론으로 확대할 수는 없습니다. 정책별 표본 수와 배치 차이를 함께 고려해야 합니다.

내부저항과 온도도 초기 후보 피처로 포함했지만, 최종 성능 비교에서 이 피처들을 넣은 선형 모델은 Batch 2에 일반화되지 않았습니다. 특정 신호가 EDA에서 Cycle Life와 상관을 보이는 것만으로 예측에 유용하다고 단정할 수 없고, hold-out과 별도 batch 평가를 거쳐야 합니다. 상세 그래프와 탐색은 [EDA 노트북](notebooks/01_EDA.ipynb)에 정리했습니다.

## 피처 엔지니어링과 모델링

기본 6개 피처는 모두 초기 관측 구간에서 계산했습니다.

| 피처 | 정의 및 사용 이유 |
| --- | --- |
| `dq_log_variance` | Cycle 100−10의 Qdlin 차이 분산을 로그 변환. 초기 ΔQ 관계를 반영 |
| `early_QD_mean` | 2–100사이클의 유효 QD 평균. 초기 가용 용량 수준 반영 |
| `early_QD_slope` | 50–100사이클 QD 선형 기울기. 초기 용량 감소 경향 반영 |
| `early_IR_mean` | 2–100사이클 내부저항 평균. 전기화학적 상태 변화 후보 신호 |
| `early_Tavg_mean` | 2–100사이클 평균 온도. 초기 발열 특성 반영 |
| `charge_C_mean` | 초기 충전 전류에서 계산한 평균 C-rate. 명목 용량 1.1 Ah 기준 |

`ΔQ(V)`는 전압 2.0–3.5 V 구간에서 계산했습니다. QD 피처는 초기 측정 이상치가 평균과 기울기를 왜곡하지 않도록 초기 기준 용량을 이용해 유효 범위를 정했습니다. 결측값 대체와 표준화는 학습 fold 안에서만 적합했습니다.

후보는 중앙값 기준선, ΔQ 단일 변수 선형 회귀, 기본 6개 피처의 Elastic Net·Ridge·Random Forest, 충전 정책을 추가한 Elastic Net입니다. Batch 1에서 충전 정책 그룹을 기준으로 내부 hold-out과 grouped cross-validation을 수행했습니다. 후보 선택은 Batch 1 hold-out MAPE를 기준으로 하고, 선택한 모델을 Batch 1 전체로 다시 학습했습니다. Batch 2와 Batch 3는 모델 선택 및 튜닝에 사용하지 않았습니다.

## 모델 결과와 선택 근거

| 후보 모델 | Batch 1 CV MAPE | Batch 1 Valid MAPE | Batch 2 Test MAPE | Batch 3 추가 MAPE |
| --- | ---: | ---: | ---: | ---: |
| 중앙값 기준선 | 20.24% | 16.49% | 72.66% | 20.20% |
| ΔQ 단일 선형 회귀 | 7.29% | 13.14% | 31.53% | 12.59% |
| 기본 6개 피처 Elastic Net | **6.98%** | 10.77% | 67.77% | 24.88% |
| 기본 6개 피처 Ridge | 9.26% | 11.19% | 66.43% | 23.43% |
| 충전 정책 확장 Elastic Net | 6.87% | 10.77% | 74.63% | 23.92% |
| **기본 6개 피처 Random Forest (선택)** | 10.66% | **10.16%** | **33.11%** | **14.10%** |

Elastic Net은 Batch 1 CV MAPE가 가장 낮았지만, Batch 1 hold-out에서 Random Forest가 10.16%로 가장 낮은 MAPE를 기록했습니다. 프로젝트의 선택 기준을 hold-out 성능으로 두었기 때문에 Random Forest를 최종 후보로 택했습니다. Valid는 11개 셀뿐이므로 0.61%p 차이를 안정적인 우위로 단정하기 어렵습니다. 따라서 이 선택은 현재 고정 분할에서의 결과이지, 모든 batch와 운전 조건에서 Random Forest가 더 우수하다는 뜻은 아닙니다.

ΔQ 단일 선형 회귀는 Batch 2 MAPE가 31.53%로 선택 모델보다 낮았지만, Batch 1 hold-out MAPE는 13.14%로 더 높았습니다. 최종 테스트 결과를 보고 모델을 교체하면 테스트셋에 과적합하는 선택이 되므로, 사전에 정한 Batch 1 기준을 유지했습니다. 이 차이는 ΔQ가 유망한 신호이면서도 현재 표본·분포에서 단일 변수만으로 안정적인 모델 선택 근거가 되지는 않는다는 점을 보여줍니다.

선택 모델의 성능 보고는 다음과 같습니다.

| 구분 | MAPE | 의미 |
| --- | ---: | --- |
| Train (Batch 1 nested grouped CV) | 10.66% | development 35개 셀의 out-of-fold 예측 |
| Valid (Batch 1 hold-out) | 10.16% | 정책 그룹으로 분리한 11개 셀 |
| Test (Batch 2) | 33.11% | 라벨 보유 39개 셀에 대한 필수 배치 평가 |
| Test (Batch 3, 추가) | 14.10% | 라벨 보유 44개 셀에 대한 추가 평가 |

Valid−Train 차이는 -0.50%p, Test−Valid는 +22.95%p, Batch 2−Batch 3은 +19.01%p입니다. 학습 내부 성능과 Batch 2 성능의 차이가 크고 batch별 평가 차이도 큽니다. 따라서 내부 검증 결과만으로 다른 실험 조건에 대한 일반화 성능을 예상하기 어렵습니다. 모든 후보의 MAE·RMSE와 셀별 예측은 `results/model_performance.csv`, `results/test_predictions.csv`에서 확인할 수 있습니다.

## 트러블슈팅: 초기 결과에서 최종 결과까지

초기 구현의 기본 6개 피처 Elastic Net은 Batch 2에서 MAPE 53.57%를 기록했습니다. 데이터 변환과 검증 절차를 다시 확인한 뒤 QD 이상치 처리, ΔQ의 전압 범위, 평균 C-rate 기준을 정리하고, DAY 1에서 제안한 ΔQ 단일 모델 및 충전 정책 확장 후보를 추가해 Batch 1 내부 검증 기준으로 비교했습니다. 수정 후 Batch 1 hold-out에서 선택된 Random Forest는 Batch 2 MAPE 33.11%를 기록해 초기 결과보다 20.46%p 낮았습니다.

이 개선은 여러 피처 처리와 모델 비교 절차를 함께 바꾼 뒤 나타났기 때문에 어느 한 수정사항의 효과라고 분리해 해석할 수 없습니다. 또한 낮아진 테스트 오차가 Batch 2의 분포 문제를 해결한 것은 아닙니다. 선택 모델은 Batch 2의 단수명 그룹에서 실제 Cycle Life 평균 449사이클을 평균 622사이클로 예측했고, 그룹 MAPE는 39.10%였습니다. 실제보다 약 173사이클 길게 예측하는 편향은 운영상 중요한 위험으로 남아 있습니다.

## ESS 운영 관점의 해석

초기 100사이클만으로 전체 Cycle Life를 추정하는 모델은 운영 초기의 셀 상태를 비교해 **추가 점검이 필요한 셀을 선별하거나**, 교체 계획·예비 셀 확보를 미리 검토하는 보조 정보가 될 수 있습니다. 초기 ΔQ 신호가 수명과 강하게 연관되고, 전체 QD 곡선에서 짧은 수명 셀의 Knee가 일찍 나타났다는 결과는 조기 상태 평가를 탐색할 가치가 있음을 뒷받침합니다.

다만 현재 모델은 Batch 2의 짧은 수명 셀을 평균 약 173사이클 과대 예측했습니다. 이 값을 현장의 남은 운전 가능 사이클로 받아들이면 점검·교체 시점을 늦추거나, 계획된 가용 용량을 과대평가할 수 있습니다. 그러므로 현재 결과는 자동 교체 결정이나 보증 판단에 사용하기에 충분하지 않습니다. 특히 Cycle Life 예측은 셀 단위 실험의 수명 타깃이며, 현장 ESS 팩의 RUL과 같지 않습니다. 팩 구성, 셀 간 편차, 온도·부하·충방전 제어, 정비 이력과 현장 EOL 기준을 추가로 반영해야 합니다.

현장 적용을 검토하려면 짧은 수명 사례를 포함한 독립 학습 자료를 확보하고, 운영 환경이 다른 기간·사이트에서 외부 검증해야 합니다. 또한 단일 예측값과 함께 예측 구간 및 오차 상한을 제공하고, 실제 SOH/RUL·정비 결과와 주기적으로 대조해야 합니다. 그 전까지는 모델을 점검 우선순위 결정의 참고 자료로 제한하고, 셀 수준의 실측 상태와 안전 기준을 우선해야 합니다.

## 실행 환경

이 프로젝트는 `pyproject.toml`에 직접 의존성을 선언하고 `uv.lock`으로 버전을 고정합니다. `requirements.txt`는 호환 설치용으로 lock 파일에서 생성한 목록입니다. Python 3.11 또는 3.12와 [uv](https://docs.astral.sh/uv/)를 사용하세요.

```bash
# macOS에서 uv가 아직 없다면
brew install uv

# 저장소를 받은 뒤 의존성 설치 및 가상환경 동기화
uv sync --locked
```

MAT 파일을 `data/`에 저장한 뒤 다음 명령으로 피처를 만들고 평가합니다.

```bash
uv run python -m src.features --data-dir ./data
uv run python -m src.train --evaluate-batch3
```

노트북을 실행하려면:

```bash
uv run jupyter lab
```

저장소의 노트북 순서는 `notebooks/01_EDA.ipynb` → `notebooks/02_feature_engineering.ipynb` → `notebooks/03_modeling.ipynb`입니다. `kagglehub`는 EDA 노트북의 데이터셋 다운로드 셀에서 사용하며, 직접 내려받은 MAT 파일을 쓰는 경우에는 `data/README.md`의 파일 배치 안내를 따르면 됩니다.
